# Archon

<ZoomImage src="/docs/images/services/archon-logo.svg" alt="Archon" />

## What is Archon?

Archon is a workflow engine for AI coding agents. Instead of asking an AI to "fix this bug" and hoping it follows your process, you define your development workflow as a YAML file - planning, implementation, validation, review, PR creation - and Archon executes those steps in order, every time. The AI provides the intelligence at each step; Archon provides the structure.

The core insight is that the problem with AI coding agents is not the intelligence - it is the non-determinism. The same prompt produces different results each run: sometimes it skips tests, sometimes it writes a PR description that ignores your template, sometimes it forgets to plan before implementing. Archon fixes this by separating what needs to be repeatable (the workflow structure) from what should be flexible (the AI reasoning within each step).

Archon ships with 17 built-in workflows covering common tasks: fixing GitHub issues, implementing features, reviewing PRs, resolving merge conflicts, and more. Each workflow run gets its own isolated git worktree, so you can run multiple workflows in parallel against the same repo without conflicts. You can also define custom workflows in `.archon/workflows/` and commit them to your repo so your whole team runs the same process.

The Coolify template deploys the full Archon server with its web dashboard (port `3000`) and a bundled PostgreSQL database.

## Deploy on Coolify

Coolify deploys a two-container stack:

- **`app`** - The Archon server: web UI, REST API, workflow executor, and platform adapters (Slack, Telegram, Discord, GitHub webhooks)
- **`postgres`** - PostgreSQL 17 for storing conversations, workflow runs, registered projects, and message history

The database password is auto-generated by Coolify and injected into both containers automatically.

<Callout type="warn">
Archon requires an AI provider credential to function. Set either `CLAUDE_CODE_OAUTH_TOKEN` or `CLAUDE_API_KEY` before your first deploy - see the Required Environment Variables section below.
</Callout>

## Required Environment Variables

Archon uses Claude Code to execute workflow steps. You must provide at least one of these credentials. Archon will not be able to run any workflow without one, even though the deployment itself will not be blocked.

| Variable | Description |
|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | OAuth token for Claude Code. Recommended - uses your Claude subscription and does not incur per-token API charges. Run `claude setup-token` in a local terminal where Claude Code is installed to generate one. |
| `CLAUDE_API_KEY` | API key from [console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys?utm_source=coolify.io). Alternative to the OAuth token - charges apply at standard API rates. |

You only need one. Use the OAuth token if you have Claude Code installed locally. Use the API key in CI or headless environments without Claude Code.

## Environment Variables

### Logging and Concurrency

| Variable | Default | Description |
|---|---|---|
| `LOG_LEVEL` | `info` | Verbosity of application logs. Options: `debug`, `info`, `warn`, `error`. |
| `MAX_CONCURRENT_CONVERSATIONS` | `10` | Maximum number of simultaneous AI conversations. Lower this if the host is under memory pressure. |

### Platform Integrations

All platform integrations are optional. Set only the ones you intend to use.

| Variable | Default | Description |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | *(empty)* | Bot token from Telegram's @BotFather. Enables running workflows by messaging your Telegram bot. |
| `SLACK_BOT_TOKEN` | *(empty)* | Bot token from your Slack app. Required for the Slack adapter. |
| `SLACK_APP_TOKEN` | *(empty)* | App-level token (starts with `xapp-`). Also required for the Slack adapter alongside `SLACK_BOT_TOKEN`. |
| `DISCORD_BOT_TOKEN` | *(empty)* | Discord bot token. Enables running workflows from a Discord server. |
| `GH_TOKEN` | *(empty)* | GitHub personal access token. Used for PR creation, issue interaction, and code checkout. Alias for `GITHUB_TOKEN`. |
| `GITHUB_TOKEN` | *(empty)* | Same as `GH_TOKEN`. Set one or the other. |
| `WEBHOOK_SECRET` | *(empty)* | Secret for verifying incoming GitHub webhook payloads. Set this when configuring repo webhooks to trigger workflows on push or PR events. |

## What to do after deploying

1. **Open the Archon web UI** by clicking the **Open** button in Coolify. This takes you to the Archon dashboard at port `3000`.

2. **Register a project** - click the **+** next to "Project" in the chat sidebar. Enter a GitHub URL or a local path to the repository you want to run workflows against.

3. **Start a conversation** - type a message describing what you want, such as "Fix issue #42" or "What workflows do I have available?" Archon will select the appropriate workflow and begin executing it.

4. **Monitor progress** - workflow steps appear in real time in the chat. Check the **Dashboard** page to see running and completed workflow runs filtered by project, status, and date.

5. **Set up a platform integration** (optional) - to trigger workflows from Slack, Telegram, or GitHub webhooks, add the relevant tokens in the **Environment Variables** tab in Coolify and redeploy.

<Callout type="info">
Archon volumes persist your registered projects, conversation history, and workflow run logs across container restarts and redeployments. To reset to a clean state, delete the `archon_data` and `archon_user_home` volumes from the Coolify storage panel.
</Callout>

## Troubleshooting

**Container exits immediately or the web UI shows a connection error on first start**

The `app` container waits for `postgres` to pass its healthcheck before starting. On a slow host or first deploy, PostgreSQL can take 20-30 seconds to initialize. If `app` exits before `postgres` is ready, Docker restarts it automatically. Wait a minute, then check if both containers are healthy in the Coolify service view.

**"No AI credentials configured" or workflow steps fail immediately**

Archon requires either `CLAUDE_CODE_OAUTH_TOKEN` or `CLAUDE_API_KEY` to run workflow steps. Go to the **Environment Variables** tab in Coolify, add your credential, and click **Save** then **Redeploy**.

**OAuth token stops working after a few weeks**

Claude Code OAuth tokens expire. Run `claude setup-token` locally again to generate a new token, update `CLAUDE_CODE_OAUTH_TOKEN` in Coolify's **Environment Variables** tab, and redeploy. Alternatively, switch to a long-lived `CLAUDE_API_KEY`.

**GitHub operations fail (PR creation, checkout, issue comments)**

GitHub operations require `GH_TOKEN` or `GITHUB_TOKEN` set to a personal access token with `repo` scope. Add the token in the **Environment Variables** tab and redeploy.

**Workflow was triggered but nothing appears in the web UI**

All platform adapter conversations (Slack, Telegram, GitHub webhooks) appear in the Archon web UI sidebar. If a workflow triggered from a platform adapter is not showing up, check that the relevant token is set correctly and set `LOG_LEVEL=debug`, then redeploy to see connection errors in the container logs.

**Stale configuration after changing environment variables**

Archon writes some configuration to the `archon_data` volume on first start. If a changed environment variable does not take effect after redeploying, open the Coolify terminal into the `app` container and check `/.archon/` for any persisted config files that may need to be cleared.
