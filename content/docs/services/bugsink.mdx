## What is Bugsink?

[Bugsink](https://www.bugsink.com/?utm_source=coolify.io) offers [error tracking](https://www.bugsink.com/error-tracking/?utm_source=coolify.io) for your applications with
full control through self-hosting.

- [Built to self-host](https://www.bugsink.com/built-to-self-host/?utm_source=coolify.io)
- [Sentry-SDK compatible](https://www.bugsink.com/sentry-sdk-compatible/?utm_source=coolify.io)
- [Scalable and reliable](https://www.bugsink.com/scalable-and-reliable/?utm_source=coolify.io)

## Database

Since Coolify v4.7.0, a new Bugsink service uses Bugsink 2 with a PostgreSQL 17 database.

### Stop the disk growth of an existing MySQL service

An older Bugsink service uses MySQL. MySQL writes binary logs that can fill the disk until Bugsink stops. To stop this:

1. Open the **Terminal** of the service, select the `mysql` container, and connect to MySQL as root with `mysql -u root -p`. The root password is in **Environment Variables**.
2. Delete the existing binary logs:

   ```sql
   PURGE BINARY LOGS BEFORE NOW();
   ```

3. Open **Configuration > General > Edit Compose File** and add this line to the `mysql` service:

   ```yaml
   command: ['--disable-log-bin']
   ```

4. Save the Compose file and restart the service.

The service continues to use MySQL. Coolify does not move the data to PostgreSQL.
