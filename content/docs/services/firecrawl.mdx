# Firecrawl

<ZoomImage src="/docs/images/services/firecrawl-logo.svg" alt="Firecrawl" />

## What is Firecrawl?

Firecrawl is an open-source web scraping and crawling API that converts any website into LLM-ready data. Give it a URL and it returns clean markdown, structured JSON, or a screenshot. It handles JavaScript-rendered pages, anti-bot measures, proxy rotation, and rate limiting with no configuration required on your end.

Beyond single-page scraping, Firecrawl can crawl entire sites, discover all URLs on a domain, run batch scrape jobs across thousands of URLs, search the web and return full page content from results, and interact with pages using AI prompts. It is widely used as a data source for AI agents and RAG pipelines.

Firecrawl is available as a hosted cloud service at [firecrawl.dev](https://firecrawl.dev?utm_source=coolify.io), or fully self-hosted. This Coolify template runs the complete self-hosted stack, exposing the API on port `3002`.

## Deploy on Coolify

Coolify deploys a six-container stack:

- **`api`** - The Firecrawl API server. Exposes the REST API on port `3002` and handles all request routing, job dispatch, and response formatting.
- **`playwright-service`** - Headless Chromium browser for scraping JavaScript-rendered pages. The `api` container calls this service internally.
- **`redis`** - Job queue backend and rate-limit store. Used by the `api` container for all async operations.
- **`rabbitmq`** - Message broker for worker coordination. Required for the crawl and batch-scrape job queues.
- **`nuq-postgres`** - PostgreSQL with the `pg_cron` extension. Stores crawl state, job metadata, and deduplication records.
- **`nuq-postgres-init`** - One-shot init container that runs the NUQ schema migration against `nuq-postgres` on every deploy. It exits after completion - this is expected behavior.

The following credentials are auto-generated by Coolify and require no manual configuration:

- API key for authenticating requests to the Firecrawl API (`TEST_API_KEY`)
- Queue dashboard password (`BULL_AUTH_KEY`)
- PostgreSQL username and password
- Redis password
- RabbitMQ username and password

On first deploy, expect the full stack to take 60-90 seconds to become healthy.

## What to do after deploying

1. **Find your API key.** Go to the **Environment Variables** tab in Coolify and look for `TEST_API_KEY`. This is the Bearer token you will use to authenticate all API requests. Copy it.

2. **Make a test scrape request** to confirm the API is responding:
   ```bash
   curl -X POST https://your-firecrawl-url/v1/scrape \
     -H "Authorization: Bearer YOUR_TEST_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"url": "https://example.com", "formats": ["markdown"]}'
   ```
   A successful response returns a `data` object with a `markdown` field containing the page content.

3. **Access the queue dashboard** (optional) to monitor job status and worker activity. Open:
   ```
   https://your-firecrawl-url/admin/YOUR_BULL_AUTH_KEY/queues
   ```
   Replace `YOUR_BULL_AUTH_KEY` with the value of the `BULL_AUTH_KEY` environment variable from the Coolify **Environment Variables** tab.

4. **Enable the `/extract` endpoint** (optional) - this endpoint uses an LLM to extract structured data from pages. Set `OPENAI_API_KEY` (or `OPENAI_BASE_URL` for a compatible provider) in the Environment Variables tab and redeploy.

## Environment Variables

### API authentication

| Variable | Default | Description |
|---|---|---|
| `TEST_API_KEY` | *(auto-generated)* | Bearer token for all Firecrawl API requests. Retrieve this from the **Environment Variables** tab. |
| `BULL_AUTH_KEY` | *(auto-generated)* | Password for the Bull queue dashboard at `/admin/<key>/queues`. |
| `USE_DB_AUTHENTICATION` | `false` | When `false`, authentication is **not enforced** - the API accepts requests without any token. `TEST_API_KEY` is still generated and can be used by SDKs or clients that require a key, but it is not required. Set to `true` to enforce authentication via database-managed API keys (requires additional Supabase setup not covered by this template). |
| `AUTUMN_SECRET_KEY` | *(empty)* | API key for [Autumn](https://useautumn.com?utm_source=coolify.io), an optional billing and credits management integration. Leave blank if you do not use Autumn. |

<Callout type="warn">
With `USE_DB_AUTHENTICATION=false` (the default), the Firecrawl API accepts requests without any authentication token. If your instance is publicly reachable, ensure it is behind a reverse proxy with access controls, or set `USE_DB_AUTHENTICATION=true` and configure Supabase.
</Callout>

### Performance tuning

| Variable | Default | Description |
|---|---|---|
| `NUM_WORKERS_PER_QUEUE` | `8` | Worker threads per job queue. Increase on high-CPU hosts for higher throughput. |
| `CRAWL_CONCURRENT_REQUESTS` | `10` | Maximum concurrent outbound HTTP requests during a crawl. Also controls the Playwright browser pool size. |
| `MAX_CONCURRENT_JOBS` | `5` | Maximum number of crawl jobs running in parallel. |
| `BROWSER_POOL_SIZE` | `5` | Number of Playwright browser instances to keep warm. Higher values use more RAM but reduce cold-start latency on browser-rendered pages. |
| `HARNESS_STARTUP_TIMEOUT_MS` | `60000` | Milliseconds to wait for the harness workers to initialize before marking startup as failed. |

### LLM provider (for `/extract` endpoint)

The `/extract` endpoint extracts structured data from pages using an LLM. It is disabled if none of these are set.

| Variable | Default | Description |
|---|---|---|

| `OPENAI_BASE_URL` | *(empty)* | Custom base URL for an OpenAI-compatible API (Azure, Ollama, LM Studio, etc.). Leave blank to use `api.openai.com`. |
| `MODEL_NAME` | *(empty)* | LLM model to use for extraction. Defaults to the provider default if not set. |
| `MODEL_EMBEDDING_NAME` | *(empty)* | Embedding model for semantic similarity in extraction tasks. |
| `OLLAMA_BASE_URL` | *(empty)* | Base URL for an Ollama instance (alternative to `OPENAI_BASE_URL`). |

## Troubleshooting

**`api` container keeps restarting on first deploy**

The `api` container waits for `redis`, `rabbitmq`, and the database init to all be healthy before it starts. On first deploy, PostgreSQL needs time to initialize and RabbitMQ needs time to set up its schema. The `api` container will restart several times while waiting - this is normal and should settle within 90 seconds. If it does not, check the logs of the `nuq-postgres` and `rabbitmq` containers for errors.

**`nuq-postgres-init` is shown as stopped or failed in Coolify**

This is expected. `nuq-postgres-init` is a one-shot migration runner. It connects to `nuq-postgres`, runs the schema SQL, and exits with code 0. The `api` container starts after this container finishes, not after it stays running.

**API requests return 401 Unauthorized**

This template ships with `USE_DB_AUTHENTICATION=false`, which means the API does **not** enforce authentication. If you are seeing 401s, you may have overridden `USE_DB_AUTHENTICATION=true`. In that mode, every request must include `Authorization: Bearer <key>` using the value of `TEST_API_KEY` from the Environment Variables tab.

**`/extract` endpoint returns an error about LLM configuration**

The `/extract` endpoint requires a connected LLM provider. Set `OPENAI_API_KEY` in the Environment Variables tab and redeploy. For a non-OpenAI provider, set `OPENAI_BASE_URL` to a compatible endpoint (e.g., a local Ollama instance) and set `MODEL_NAME` to the model you want to use.

**Queue dashboard returns 403 or Not Found**

The dashboard URL format is `/admin/<BULL_AUTH_KEY>/queues` - the key goes between `/admin/` and `/queues`. Copy the exact value of `BULL_AUTH_KEY` from the Environment Variables tab.
