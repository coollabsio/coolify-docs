## What is OpenObserve?

OpenObserve is a cloud-native observability platform built in Rust. It ingests, stores and queries logs, metrics, traces, real user monitoring (RUM) data and session replays in a single binary, positioning itself as a self-hosted alternative to Elasticsearch, Splunk and Datadog. Storage is columnar (Parquet) and compaction-aware, so disk usage stays low even at high ingest volumes.

## Deployment

The Coolify template deploys OpenObserve in **single-node mode**:

- **Image:** `public.ecr.aws/zinclabs/openobserve` (open-source, AGPL-3.0)
- **Port:** 5080 (web UI and ingest endpoints)
- **Metastore:** SQLite (built into the container)
- **Data storage:** Local disk, persisted via the `openobserve-data` named volume mounted at `/data`
- **No external services required** — Postgres / NATS / S3 are only needed for clustered HA mode, which is out of scope for the single-node template.

## Default credentials

On first deploy:

- **Email:** `root@example.com` (override via the `ZO_ROOT_USER_EMAIL` environment variable before first start)
- **Password:** auto-generated by Coolify and exposed as the `SERVICE_PASSWORD_OPENOBSERVE` environment variable. Copy it from the service's environment list in the Coolify UI.

Root credentials are only used during first startup; subsequent restarts read the user from the metastore.

## Notable environment variables

The template ships with a few opinionated defaults that you can override from the Coolify UI:

- `ZO_TELEMETRY=false` — opts out of anonymous usage reporting by default. Set to `true` if you want to help OpenObserve with usage statistics.
- `ZO_COOKIE_SECURE_ONLY=true` — restricts auth cookies to HTTPS, matching Coolify's Traefik-managed TLS endpoints. Set to `false` if you front the service with plain HTTP for any reason.
- `ZO_ROOT_USER_EMAIL` — change this before first start to use a different admin email.

For the full env reference, see the [OpenObserve environment variables documentation](https://openobserve.ai/docs/environment-variables/?utm_source=coolify.io).

## Sending data in

After deployment, the same FQDN that serves the UI also accepts ingest:

- **OpenTelemetry (OTLP/HTTP):** `POST <fqdn>/api/<org>/v1/traces` (and `/v1/logs`, `/v1/metrics`)
- **Elasticsearch-compatible bulk API:** `POST <fqdn>/api/<org>/_bulk`
- **Fluent Bit, Vector, FluentD, Logstash, syslog, Prometheus remote write** — all supported

See the OpenObserve [data ingestion guide](https://openobserve.ai/docs/ingestion/?utm_source=coolify.io) for sender-specific examples.
