# Server Validation Issues

You cannot validate your server because of a validation error.

<Accordions type="multiple">

<Accordion title="Invalid private key (`error in libcrypto`)">

### Symptoms
- During validation you receive an `error in libcrypto` error.

### Solution
Check the private key added to Coolify. It is probably missing a few things, like the `-----BEGIN OPENSSH PRIVATE KEY-----` and `-----END OPENSSH PRIVATE KEY-----` lines.

</Accordion>

<Accordion title="Permission denied (publickey)">

### Symptoms
- During validation you receive: `Server is not reachable. Reason: root@host.docker.internal: Permission denied (publickey).`

### Solution
Coolify cannot reach the server because its public key is missing from the account's `~/.ssh/authorized_keys` file. During installation, a public key is generated at `/data/coolify/ssh/keys/id.root@host.docker.internal.pub` and added to `~/.ssh/authorized_keys` automatically.

If it was not added, append it manually on the server:

```bash
cat /data/coolify/ssh/keys/id.root@host.docker.internal.pub >> ~/.ssh/authorized_keys
```

</Accordion>

<Accordion title="The SSH host key of this server changed">

### Symptoms
- Validation or a deployment fails with: `The SSH host key of this server changed, so Coolify did not connect.`
- The server **General** page shows **The SSH host key of this server changed**.

### Solution
Coolify refuses a changed host key in enforce mode. This is expected after you reinstall the server. Otherwise, another machine can answer at the server address.

Compare the new key with the key on the server, then select **Trust new key** or **Reset** under **Servers > your server > Security**. See [SSH host key](/core/infrastructure/servers/security#ssh-host-key).

</Accordion>

<Accordion title="Maximum number of sessions (8192) reached">

### Symptoms
- The server refuses new SSH logins with `Maximum number of sessions (8192) reached`.
- The server becomes unreachable in Coolify, also when SSH settings did not change.

### Solution
Coolify versions before v4.7.0 opened three SSH logins for each connection check. On some servers, these logins left stuck sessions. Update Coolify, then remove the stuck sessions on the server with the provider console or an open SSH session:

```bash
systemctl restart systemd-logind
```

Then validate the server again.

</Accordion>

</Accordions>
