# Connection Unstable

If Coolify intermittently loses access to a server, the cause is usually a firewall on the server, at your hosting provider, or between Coolify (or Coolify Cloud) and the server that drops or rate-limits SSH connections.

Use the SSH port configured for the server in Coolify in every command below. It can differ from port `22`.

## Symptoms

- The server is sometimes reachable and sometimes not.
- You receive many connection-lost notifications for the server.

## Diagnosis

Coolify opens new SSH connections for server checks, deployments, and file transfers. A rate limit on the SSH port can block these connections even when your own SSH session works.

1. Check the UFW rules:

   ```sh
   sudo ufw status numbered
   ```

   A `LIMIT` rule for the SSH port is the most common cause. UFW `LIMIT` blocks a source address that opens 6 or more connections within 30 seconds, and the rate cannot be changed. There are usually separate IPv4 and IPv6 rules.

2. Check iptables for rate-limiting rules on the SSH port, such as rules using the `recent`, `limit`, or `hashlimit` modules:

   ```sh
   sudo iptables -L -v -n
   sudo ip6tables -L -v -n
   ```

3. Check the logs around the time of a failed connection, for example `/var/log/ufw.log`, `/var/log/auth.log`, and `/var/log/kern.log`. Blocked connections from the Coolify source address confirm a firewall problem.

4. Check any firewall configured with your hosting provider.

## Solution

<Callout type="warning" title="Keep SSH access open">
Keep a working administrator SSH session open while changing firewall rules. A wrong SSH rule can lock you out of the server.
</Callout>

1. Find the source addresses Coolify connects from:
   - For Coolify Cloud, use the current [IPv4](https://coolify.io/ipv4.txt) and [IPv6](https://coolify.io/ipv6.txt) lists.
   - For self-hosted Coolify, use the public IP address of the server running Coolify, as seen by the managed server.

2. Add an allow rule for each source address before the `LIMIT` rule. UFW applies the first matching rule, so insert the new rules at the top:

   ```sh
   sudo ufw insert 1 allow proto tcp from SOURCE_ADDRESS to any port SSH_PORT
   ```

   Replace `SOURCE_ADDRESS` with the address or CIDR, and `SSH_PORT` with the SSH port. This keeps the rate limit for other sources.

3. In Coolify, open the server and select **Validate connection** (or **Revalidate connection** on a validated server) to confirm that Coolify can connect. From another terminal, open a second SSH session to confirm your own access.

4. If you want to remove the `LIMIT` rule instead, run `sudo ufw status numbered` again and delete it by its current number with `sudo ufw delete <rule_number>`. Rule numbers change after each deletion, so check the list again before deleting the IPv6 rule. Then restrict SSH to known source addresses, as described in [Firewall](/core/infrastructure/servers/firewall).

For iptables rate limits, add an `ACCEPT` rule for the Coolify source addresses above the rate-limiting rule.

See [Firewall](/core/infrastructure/servers/firewall) for the ports Coolify needs and for Docker port guidance.
