# Clone or move a database

Open a database and select **Resource Operations**. This page provides these actions:

- **Clone to another destination** creates a second database resource on another server or network destination.
- **Clone to another environment** copies the configuration into another project environment on the same server and network.
- **Move Resource** changes the project and environment of the existing database on the same Coolify instance.

A clone starts with a separate persistent volume. It is empty unless you select **Clone volume data**. A move changes organization without copying data.

<Tabs id="database-resource-operations" items={['Clone resource', 'Move resource']}>
<Tab value="Clone resource">

Clone a database when you need the same configuration on another server or network destination.

<Callout type="warning" title="Database data is copied only on request">

Coolify copies the database configuration, environment variables, storage definitions, scheduled backup configuration, and tags. Select **Clone volume data** to also copy the data of the database volume, also to another server. A running source database is stopped while the data is copied and started again afterwards, so the copy is consistent. Bind mounts (host paths) are not copied. A clone is not a backup or a replica.

</Callout>

<Steps>
<Step>

### Prepare the destination

Confirm that the target server can host resources and has the network destination that the clone should use. Build servers cannot host running database resources.

</Step>
<Step>

### Select the destination

Open **Resource Operations**. Under **Clone to another destination**, choose **Server**, then **Network destination**. To copy the data, select **Clone volume data**.

</Step>
<Step>

### Clone and review

Select **Clone Resource**. The clone is created stopped. Review its generated name, image, credentials, internal and public connection details, storage mounts, environment variables, backup settings, ports, SSL settings, and tags before starting it.

Give the clone a distinct domain or port mapping. Do not point production applications at it until it has the required data and you have tested the connection.

</Step>
</Steps>

### Clone into another environment

Under **Clone to another environment**, select **Project** and **Environment**, then select **Clone resource**. Review the stopped clone. If you did not select **Clone volume data**, restore the required data before you start it.

</Tab>
<Tab value="Move resource">

Move a database when it should belong to another project or environment on the same Coolify instance. Moving does not change the database's server, network destination, configuration, or persistent volume.

<Callout type="info" title="Move is not a server migration">

The running database is not stopped and its data is not copied. To run a second copy on another server, use **Clone Resource** and then restore or copy the data separately.

</Callout>

<Steps>
<Step>

### Choose the target project

Open **Resource Operations**. Under **Move Resource**, choose **Project**.

</Step>
<Step>

### Choose the target environment

Choose **Environment**. Coolify excludes the database's current environment. Select an environment in the current project or another project.

</Step>
<Step>

### Move and verify

Select **Move Resource**. Coolify changes the database's project and environment without stopping the running resource. Open the database from its new location and verify its status, internal URL, backups, webhooks, and related application references.

</Step>
</Steps>

</Tab>
</Tabs>
