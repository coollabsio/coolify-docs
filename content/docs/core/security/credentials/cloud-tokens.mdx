# Cloud tokens

Coolify uses cloud tokens to connect to supported cloud providers. A cloud token belongs to the active Coolify team and can be used when creating or managing a server in that provider account.

Only team administrators and owners can manage cloud tokens. Coolify encrypts the token value in its database and does not display the saved value again.

<Callout type="warning" title="Treat cloud tokens as passwords">
Create a dedicated provider token for Coolify, grant only the access it needs, and store the original value in a secret manager. Revoke and replace the token immediately if it is exposed.
</Callout>

## Create a provider token

Choose the provider account where Coolify will create and manage servers. Most readers need only one of these procedures.

<Tabs id="cloud-token-provider" items={['Hetzner', 'DigitalOcean', 'Vultr']}>
<Tab value="Hetzner" icon={ServerCloud}>

Hetzner tokens belong to one project. Create the token in the project where Coolify should manage servers.

<Steps>
<Step>

### Open the Hetzner project

Open the [Hetzner Cloud Console](https://console.hetzner.cloud/projects), then select the required project.

</Step>
<Step>

### Open API tokens

Select **Security** in the project sidebar, open **API Tokens**, then select **Generate API Token**.

</Step>
<Step>

### Configure the token

Enter a description such as `coolify-shadowarcanist`, then select **Read & Write**.

Coolify needs write access to create and delete servers, upload SSH keys, control server power, and optionally enable Hetzner backups. A **Read** token may pass the initial validation but cannot perform these actions.

</Step>
<Step>

### Generate and copy the token

Select **Generate API Token**, copy the complete value, and store it securely. Hetzner does not show the token again after you close the dialog.

</Step>
</Steps>

</Tab>
<Tab value="DigitalOcean" icon={Droplet}>

Create a DigitalOcean personal access token for the team where Coolify should manage Droplets.

<Steps>
<Step>

### Open personal access tokens

Open [Applications & API](https://cloud.digitalocean.com/account/api/tokens), find **Personal access tokens**, then select **Generate New Token**.

</Step>
<Step>

### Name the token and choose an expiration

Enter a name such as `coolify-shadowarcanist`. Choose an expiration period that gives you enough time to rotate the token before it expires.

</Step>
<Step>

### Select custom scopes

Choose **Custom Scopes**, then grant these scopes:

- `account:read`
- `regions:read`
- `sizes:read`
- `image:read`
- `ssh_key:read`
- `ssh_key:create`
- `droplet:read`
- `droplet:create`
- `droplet:update`
- `droplet:delete`

These scopes let Coolify validate the account, list the options required by the server form, manage SSH keys, and create, inspect, start, or delete Droplets. **Full Access** also works but grants broader access than Coolify needs.

</Step>
<Step>

### Generate and copy the token

Select **Generate Token**, copy the complete value, and store it securely. DigitalOcean shows the token secret only once.

</Step>
</Steps>

</Tab>
<Tab value="Vultr" icon={CloudBolt}>

Create a Vultr API key for the account where Coolify should manage instances.

<Steps>
<Step>

### Open Vultr API access

Open the [Vultr API page](https://console.vultr.com/user/apiaccess/). Depending on the Vultr Console version, this page appears as **Vultr API** under **Orchestration** or as **API Access** under **Account**.

Enable API access for the Vultr user if it is disabled.

</Step>
<Step>

### Check API access control

If the Vultr account restricts API access by IP address, allow the public outbound IP address of the Coolify instance. The API requests come from Coolify, not from your browser or the server that Coolify will create.

</Step>
<Step>

### Create the API key

Under **User Access Tokens**, enter a name such as `coolify-shadowarcanist`, choose an expiration option, and select **Add Key**.

The Vultr user must be allowed to list plans, regions, operating systems, and SSH keys, and to create, inspect, start, and delete instances.

</Step>
<Step>

### Copy the API key

Copy the complete key and store it securely. Vultr does not let you recover the value after leaving the page.

</Step>
</Steps>

</Tab>
</Tabs>

## Add the token to Coolify

<Steps>
<Step>

### Open Cloud Tokens

Open **Keys & Tokens** in the Coolify sidebar, then select **Cloud Tokens**.

</Step>
<Step>

### Choose the provider

Select **+ Add**, then choose **Hetzner**, **DigitalOcean**, or **Vultr**.

</Step>
<Step>

### Enter the token details

Complete the form:

- **Token Name:** Enter a name that identifies the provider account or environment, such as `shadowarcanist-production`.
- **Description:** Optionally record the project, team, account, or intended use.
- **API Token:** Paste the complete token or API key copied from the provider.

Select **Validate & Add Token**.

</Step>
<Step>

### Confirm the token was added

After validation succeeds, Coolify closes the form and displays the new token on the **Cloud Provider Tokens** page.

</Step>
</Steps>

<Callout type="info" title="Validation checks the credential, not every permission">
Coolify validates a Hetzner token by listing servers and validates DigitalOcean and Vultr tokens through their account endpoints. A successful result confirms that the provider accepts the credential, but it does not prove that every permission required to create or manage a server is available.
</Callout>

## Manage a cloud token

Open **Keys & Tokens > Cloud Tokens**, then select a token.

- Change **Name** or **Description**, then select **Save**.
- Select **Validate** to check whether the provider still accepts the saved credential.
- Select **Delete** to remove an unused token.

The provider and creation date are read-only. Coolify does not show or replace the saved secret on this page. To rotate a credential, create a replacement at the provider, add it as a new cloud token, and move every dependent server to the replacement before revoking the previous credential.

Coolify blocks deletion while one or more servers still use the token. Do not revoke the credential at the provider until those servers have been moved to another token or are no longer managed through that provider connection.

## Troubleshooting

<Accordions type="multiple">
<Accordion title="Coolify reports Invalid API token">

Confirm that you selected the matching provider and pasted the complete token without surrounding spaces. Check that the credential has not expired or been revoked.

For Hetzner, confirm that the project still exists. For DigitalOcean, confirm that the token includes `account:read`. For Vultr, confirm that API access is enabled and that Vultr's access-control list permits requests from the Coolify instance.

</Accordion>
<Accordion title="The token validates but server actions fail">

Initial validation does not test every write operation.

- For Hetzner, use a **Read & Write** token.
- For DigitalOcean, compare the token's custom scopes with the list in the [DigitalOcean tab](#cloud-token-provider).
- For Vultr, confirm that the Vultr user can manage instances and SSH keys and that API access control permits the Coolify instance.

After correcting the provider permissions, return to the saved cloud token and select **Validate**.

</Accordion>
<Accordion title="Vultr rejects requests from Coolify">

Check **Access Control** on the Vultr API page. If an IP allowlist is enabled, it must contain the public outbound IP address of the Coolify instance.

Adding your browser's IP address or the address of the server you intend to create does not authorize requests sent by Coolify.

</Accordion>
<Accordion title="Hetzner resources are missing">

Hetzner tokens are project-specific. Confirm that the token was created in the project containing the servers, networks, firewalls, and SSH keys you expect Coolify to use.

Create and add a separate token when Coolify must work with another Hetzner project.

</Accordion>
<Accordion title="Coolify will not delete the token">

The token is still assigned to one or more servers. Move those servers to another valid provider token or remove the provider relationship before trying to delete it again.

Do not revoke the provider credential first. Coolify needs the working credential for provider-backed server actions until the dependency has been removed.

</Accordion>
</Accordions>
