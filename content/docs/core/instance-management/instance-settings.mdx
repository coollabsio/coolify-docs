# Instance settings

Instance settings control the Coolify control plane itself. These settings change the Coolify instance itself, not a project, application, database, service, or server.

<Callout type="warn" title="Coolify Cloud">
If you use **Coolify Cloud**, the Coolify team manages the Coolify instance for you. Coolify Cloud users cannot access or edit these settings.
</Callout>

<Callout type="info" title="Example Data">

The following data is used as an example in this guide. Please replace it with your actual data when following the steps:

- **Domain Name:** `shadowarcanist.com`
- **Coolify Dashboard:** `https://coolify.shadowarcanist.com`

</Callout>

Open **Settings** in the left sidebar, or visit:

```bash
https://coolify.shadowarcanist.com/settings
```

<ZoomableImage src="/docs/images/core/instance-management/general-settings-tab.webp" alt="Settings page with General selected in the instance settings navigation" />

The Settings page groups options under **Configuration** (General, Advanced, and Updates) and **Instance** (Backup, Email, Authentication, and Scheduled Jobs). Select a section from the Settings navigation, then use **Save changes** to apply your edits.

## Configuration

<Tabs id="instance-settings-configuration" items={['General', 'Advanced', 'Updates']}>
<Tab value="General" icon={Settings}>

<ZoomableImage src="/docs/images/core/instance-management/general-settings-overview.webp" alt="Open Settings, then select General in the instance settings navigation" />

Use General for the dashboard URL, HTTP-to-HTTPS behavior, instance label, timezone, and network addresses Coolify should use.

### URL

<ZoomableImage src="/docs/images/core/instance-management/general-url.webp" alt="URL field in General settings" />

This is the address you use to open the Coolify dashboard. Coolify also uses it when it needs to generate links back to the instance. If you want the dashboard to use HTTPS, the value must start with `https://`.

Enter the full dashboard URL in **URL** and click **Save changes**. Before changing it, make sure DNS for the domain points to the server where Coolify is running. If DNS validation is enabled, Coolify checks the domain. Coolify also warns you when the instance URL is already used by another resource.

**Accepted values:**
- A full URL with a protocol, for example `https://coolify.shadowarcanist.com`.
- Use `https://` when the dashboard should be served over HTTPS.
- A root domain or subdomain.

**Notes:**
- Path-based URLs such as `https://shadowarcanist.com/coolify` are not supported.
- Do not reuse an application or service domain for the dashboard. If the instance URL conflicts with a resource domain, SSL certificates and routing can become unpredictable.

---

### Redirect HTTP to HTTPS

<ZoomableImage src="/docs/images/core/instance-management/general-redirect-http-to-https.webp" alt="Redirect HTTP to HTTPS setting" />

Controls whether requests to the Coolify dashboard over HTTP are redirected to HTTPS.

Choose **Enabled** or **Disabled**, then click **Save changes**.

**Notes:**

- If a reverse proxy or Cloudflare Tunnel connects to Coolify over HTTP while users access the dashboard over HTTPS, enabling this setting can create a redirect loop. Disable the redirect in Coolify when your proxy handles HTTPS redirection.
- Keep this enabled when Cloudflare uses **Full** or **Full (Strict)** SSL.

**Accepted values:**

- Enabled: redirect HTTP requests to HTTPS.
- Disabled: do not redirect HTTP requests.

---

### Name

<ZoomableImage src="/docs/images/core/instance-management/general-name.webp" alt="Name field in General settings" />

Adds the instance name in brackets before the page title shown in the browser tab. For example, a name of `Production` appears as `[Production] Settings | Coolify`. It does not change the Coolify name or logo in the sidebar.

Update **Name** and click **Save changes**.

**Accepted values:**

- Any text value up to 255 characters.
- Leave it empty to keep the default Coolify instance name.

---

### Instance timezone

<ZoomableImage src="/docs/images/core/instance-management/general-timezone.webp" alt="Instance timezone selector in General settings" />

This timezone is used by instance-level schedules, including update checks and automatic updates. It does not change the timezone inside your applications or databases.

Search for the timezone in **Instance timezone**, select it from the list, and click **Save changes**.

**Accepted values:**

- A valid timezone identifier from the dashboard list, for example `UTC`, `Europe/Berlin`, or `America/New_York`.

**Notes:**

- Database backup schedules can use the server timezone when the server has one configured. Otherwise, they fall back to the instance timezone.

---

### Instance public IPv4

<ZoomableImage src="/docs/images/core/instance-management/general-public-ipv4.webp" alt="Instance public IPv4 field in General settings" />

Coolify normally detects the public IPv4 address of the server that runs the instance. Use this field only when the detected address is wrong, usually on servers with multiple public IPs.

Enter the IPv4 address Coolify should use and click **Save changes**.

**Accepted values:**

- Leave it empty to let Coolify use the detected address.
- A valid IPv4 address, for example `203.0.113.10`.

---

### Instance public IPv6

<ZoomableImage src="/docs/images/core/instance-management/general-public-ipv6.webp" alt="Instance public IPv6 field in General settings" />

Coolify normally detects the public IPv6 address of the server that runs the instance. Use this field only when Coolify picks the wrong IPv6 address or cannot detect it.

Enter the IPv6 address Coolify should use and click **Save changes**.

**Accepted values:**

- Leave it empty to let Coolify use the detected address.
- A valid IPv6 address, for example `2001:db8::1`.

</Tab>

## Access

### Registration

<ZoomableImage src="/docs/images/core/instance-management/advanced-registration.webp" alt="Registration setting in Advanced settings" />

Controls whether users can create their own accounts from the registration page. Choose **Anyone can register** or **Registration disabled**, then click **Save changes**.

**Accepted values:**

- **Anyone can register:** anyone who can reach the registration page can create an account.
- **Registration disabled:** only administrators can create accounts.

**Notes:**

- Keep registration disabled unless you intentionally want public self-registration.

---

### Destructive action confirmation

<ZoomableImage src="/docs/images/core/instance-management/advanced-destructive-action-confirmation.webp" alt="Destructive action confirmation setting in Advanced settings" />

Controls whether destructive actions require password and text confirmation. Choose **Require two-step confirmation** or **Skip two-step confirmation**, then click **Save changes**.

**Accepted values:**

- **Require two-step confirmation:** destructive actions require the extra confirmation step.
- **Skip two-step confirmation:** destructive actions do not require the extra confirmation step.

**Notes:**

- Skipping confirmation increases the chance of accidental deletions or unwanted changes.

---

## DNS

### DNS validation

<ZoomableImage src="/docs/images/core/instance-management/advanced-dns-validation.webp" alt="DNS validation setting in Advanced settings" />

Checks whether custom domains point to the right server before deployment. Choose **Enabled** or **Disabled**, then click **Save changes**.

**Accepted values:**

- **Enabled:** validate custom domains before deployment.
- **Disabled:** skip DNS validation.

---

### Custom DNS servers

<ZoomableImage src="/docs/images/core/instance-management/advanced-custom-dns-servers.webp" alt="Custom DNS servers field in Advanced settings" />

Changes which DNS resolvers Coolify uses for domain validation. Enter the resolver IPs in **Custom DNS servers**, then click **Save changes**.

**Accepted values:**

- Leave it empty to use the system default DNS resolvers.
- A comma-separated list of valid IPv4 or IPv6 addresses, for example `1.1.1.1,8.8.8.8`.

---

## API and MCP

### API access

<ZoomableImage src="/docs/images/core/instance-management/advanced-api-access.webp" alt="API access setting in Advanced settings" />

Controls whether authenticated requests to the Coolify REST API are allowed. Choose **Enabled** or **Disabled**, then click **Save changes**. For API tokens, follow [API tokens](/core/security/credentials/api-tokens).

**Accepted values:**

- **Enabled:** authenticated API requests are accepted.
- **Disabled:** API requests are blocked.

---

### MCP server

<ZoomableImage src="/docs/images/core/instance-management/advanced-mcp-server.webp" alt="MCP server setting in Advanced settings" />

Enables the MCP endpoint at `/mcp` for authenticated clients. Use your instance URL followed by `/mcp` and authenticate with a Sanctum bearer token created from [API tokens](/core/security/credentials/api-tokens).

**Accepted values:**

- **Enabled:** the instance MCP endpoint is available to authenticated clients.
- **Disabled:** the instance MCP endpoint is unavailable.

For the detailed guide, follow [MCP integration](/mcp/what-is-mcp).

---

### Allowed API IPs

<ZoomableImage src="/docs/images/core/instance-management/advanced-allowed-api-ips.webp" alt="Allowed API IPs field in Advanced settings" />

Restricts which source IP addresses can call the Coolify API. Enter comma-separated IPs or CIDR ranges, then click **Save changes**.

**Accepted values:**

- Empty or `0.0.0.0` allows API access from anywhere.
- Single IPv4 or IPv6 addresses, for example `192.168.1.100` or `2001:db8::10`.
- CIDR ranges, for example `10.0.0.0/8` or `203.0.113.0/24`.

**Notes:**

- Allowing access from anywhere is not recommended for production instances.

---

## Outbound endpoints

These controls limit which internal destinations Coolify can reach when making outbound requests.

### Allowed internal targets

<ZoomableImage src="/docs/images/core/instance-management/advanced-allowed-internal-targets.webp" alt="Allowed internal targets field in Advanced settings" />

Lists the internal destinations Coolify can reach when making outbound requests. Enter the hostnames, IP addresses, or CIDR ranges required by your integrations. Separate entries with commas or new lines, then click **Save changes**.

---

### Localhost targets

<ZoomableImage src="/docs/images/core/instance-management/advanced-localhost-targets.webp" alt="Localhost targets setting in Advanced settings" />

Controls whether outbound requests can target localhost addresses. Choose **Allowed** or **Blocked**, then click **Save changes**.

**Notes:**

- Loopback targets must also be included in **Allowed internal targets**.

## Interface and telemetry

### Navigation

<ZoomableImage src="/docs/images/core/instance-management/advanced-navigation.webp" alt="Navigation setting in Advanced settings" />

Enables SPA-style navigation and prefetching for smoother dashboard page transitions. Choose **SPA navigation** or **Full page navigation**, then click **Save changes**.

**Accepted values:**

- **SPA navigation:** dashboard links can prefetch and move between pages without full reloads.
- **Full page navigation:** dashboard navigation uses full page loads.

**Notes:**

- Choose full page navigation if the dashboard has navigation issues after a browser or Livewire change.

---

### Anonymous telemetry

<ZoomableImage src="/docs/images/core/instance-management/advanced-anonymous-telemetry.webp" alt="Anonymous telemetry setting in Advanced settings" />

Controls whether this instance sends an anonymous installation count to Coolify, contributing to the self-hosted installation count shown on [coolify.io](https://coolify.io/). Coolify does not store IP addresses or send error reports.

Choose **Enabled** or **Disabled**, then click **Save changes**.

**Accepted values:**

- **Enabled:** do not send anonymous installation counts.
- **Disabled:** allow anonymous installation counts.

---

### Sponsorship reminders

<ZoomableImage src="/docs/images/core/instance-management/advanced-sponsorship-reminders.webp" alt="Sponsorship reminders setting in Advanced settings" />

Controls whether Coolify displays a sponsorship popup each month. Choose **Enabled** or **Disabled**, then click **Save changes**.

**Accepted values:**

- **Enabled:** monthly sponsorship reminders can be shown.
- **Disabled:** sponsorship reminders are hidden for the instance.

---

<Tab value="Updates" icon={Refresh23}>

Updates controls version checks and automatic self-updates.

### Check frequency

<ZoomableImage src="shadow-todo" alt="Update Check Frequency setting screenshot" />

Sets how often Coolify checks for new Coolify versions and pulls new service templates from the CDN.

Set **Check frequency**, then click **Save changes**. Use **Check Now** when you want to run the check immediately.

**Accepted values:**

- `every_minute`, `hourly`, `daily`, `weekly`, `monthly`, `yearly`, or a valid cron expression.
- The default is `0 * * * *`, which checks every hour.

For the detailed guide, follow [Update Coolify](/core/instance-management/update).

---

### Automatic updates

<ZoomableImage src="shadow-todo" alt="Auto Update Enabled setting screenshot" />

Controls whether Coolify updates itself automatically.

Choose **Enabled** or **Disabled** under **Automatic updates**. If `AUTOUPDATE` is set in `/data/coolify/source/.env`, the dashboard control is disabled and you must change the environment value instead.

**Accepted values:**

- Enabled: Coolify can update itself on the configured schedule.
- Disabled: Coolify only updates when you update it manually.

---

### Update frequency

<ZoomableImage src="shadow-todo" alt="Auto Update Frequency setting screenshot" />

Sets the schedule Coolify uses when automatic updates are enabled.

Enable **Automatic updates**, set **Update frequency**, then click **Save changes**.

**Accepted values:**

- `every_minute`, `hourly`, `daily`, `weekly`, `monthly`, `yearly`, or a valid cron expression.
- The default is `0 0 * * *`, which runs every day at `00:00`.

## Backup

<ZoomableImage src="shadow-todo" alt="Coolify instance backup settings page" />

<Tabs id="instance-settings-backup" items={['Instance Database', 'Scheduled Backup', 'S3 Storage']}>
<Tab value="Instance Database" icon={Database}>

The Backup page is for the internal Coolify database. It does not back up every application volume or every external database.

### Configure Backup

<ZoomableImage src="shadow-todo" alt="Configure Backup setting screenshot" />

Creates the Coolify database resource and scheduled backup configuration needed for instance backups.

If Coolify shows **Configure Backup**, click it first. If the localhost server is not validated, validate the server before configuring backups.

**Accepted values:**

- Available only when the localhost server is functional.
- Creates or reveals the internal `coolify-db` backup configuration.

For the detailed guide, follow [Instance backup](/core/backup-and-recovery/instance-backup).

---

### Description

<ZoomableImage src="shadow-todo" alt="Description setting screenshot" />

Stores a short note for the internal Coolify database resource shown on the Backup page.

Update **Description**, then click **Save changes**.

**Accepted values:**

- Any text value, or empty if you do not need a description.

---

### UUID, Name, User, Password

<ZoomableImage src="shadow-todo" alt="UUID, Name, User, Password setting screenshot" />

Shows the internal database identity and credentials Coolify uses for its own database backup resource.

These fields are read-only on the Backup page. Change backup behavior from the Scheduled Backup section instead.

**Accepted values:**

- Read-only values generated and managed by Coolify.

</Tab>

<Tab value="Scheduled Backup" icon={Calendar}>

Scheduled Backup controls when the internal Coolify database backup runs and how long backup files are kept.

### Backup Enabled

<ZoomableImage src="shadow-todo" alt="Backup Enabled setting screenshot" />

Controls whether the scheduled backup job is active.

Toggle **Backup Enabled** in **Scheduled Backup**, then click **Save changes**.

**Accepted values:**

- Enabled: the backup schedule can run.
- Disabled: the backup schedule is kept but does not run.

---

### Backup Now

<ZoomableImage src="shadow-todo" alt="Backup Now setting screenshot" />

Queues an immediate backup run without waiting for the next scheduled time.

Click **Backup Now**. Coolify shows this action when the database resource is running.

**Accepted values:**

- A manual action; it does not change the saved schedule.

---

### Frequency

<ZoomableImage src="shadow-todo" alt="Frequency setting screenshot" />

Sets how often the instance database backup runs.

Update **Frequency** in **Scheduled Backup**, then click **Save changes**.

**Accepted values:**

- `every_minute`, `hourly`, `daily`, `weekly`, `monthly`, `yearly`, or a valid cron expression.
- For example, `0 0 * * *` or `daily`.

---

### Timezone

<ZoomableImage src="shadow-todo" alt="Timezone setting screenshot" />

Shows the timezone used for the backup schedule.

This field is read-only on the backup schedule. Change the server timezone on the server settings page, or let Coolify use the instance timezone.

**Accepted values:**

- The server timezone when configured.
- The instance timezone when the server does not define one.

---

### Timeout

<ZoomableImage src="shadow-todo" alt="Timeout setting screenshot" />

Sets the maximum time a backup job can run before Coolify treats it as timed out.

Update **Timeout** in seconds, then click **Save changes**.

**Accepted values:**

- Any integer from 60 to 36000 seconds.

---

### Local Backup Retention

<ZoomableImage src="shadow-todo" alt="Local Backup Retention setting screenshot" />

Controls how many local backup files Coolify keeps on the server.

Update the local retention limits, then click **Save changes**.

**Accepted values:**

- Number of backups to keep: integer `0` or greater.
- Days to keep backups: integer `0` or greater.
- Maximum storage in GB: number `0` or greater; decimals are accepted.
- A value of `0` means unlimited for that specific limit.

</Tab>

<Tab value="S3 Storage" icon={CloudStorage}>

S3 settings copy instance backup files to a validated S3-compatible storage target.

### S3 Enabled

<ZoomableImage src="shadow-todo" alt="S3 Enabled setting screenshot" />

Controls whether backup files are uploaded to S3-compatible storage.

Toggle **S3 Enabled**, choose a storage target, then click **Save changes**.

**Accepted values:**

- Enabled: upload backups to the selected S3 storage.
- Disabled: keep backups local only unless **Disable Local Backup** was already reset.

For the detailed guide, follow [S3 backups](/core/backup-and-recovery/instance-backup).

---

### S3 Storage

<ZoomableImage src="shadow-todo" alt="S3 Storage setting screenshot" />

Selects the validated S3 storage record used for instance backup uploads.

Create and validate an S3 storage entry first, then select it from the **S3 Storage** field.

**Accepted values:**

- One of the current team S3 storage entries.
- Unavailable when no S3 storage exists.

---

### Disable Local Backup

<ZoomableImage src="shadow-todo" alt="Disable Local Backup setting screenshot" />

Deletes the local backup file after Coolify uploads it to S3.

Enable S3 backups first, then toggle **Disable Local Backup** and click **Save changes**.

**Accepted values:**

- Enabled: remove the local file after successful S3 upload.
- Disabled: keep local backup files according to local retention rules.

---

### S3 Storage Retention

<ZoomableImage src="shadow-todo" alt="S3 Storage Retention setting screenshot" />

Controls how many S3 backup files Coolify keeps in the selected S3 storage.

Enable **S3**, update the S3 retention limits, then click **Save changes**.

**Accepted values:**

- Number of backups to keep: integer `0` or greater.
- Days to keep backups: integer `0` or greater.
- Maximum storage in GB: number `0` or greater; decimals are accepted.
- A value of `0` means unlimited for that specific limit.

</Tab>
</Tabs>

## Scheduled Jobs

<ZoomableImage src="shadow-todo" alt="Coolify scheduled job issues page" />

<Tabs id="instance-settings-scheduled-jobs" items={['Failures', 'Scheduler runs', 'Skipped']}>
<Tab value="Failures" icon={Warning22}>

The **Scheduled Jobs** page groups activity into **Failures**, **Scheduler runs**, and **Skipped**. Search, filter, sort, refresh, and page through the activity from this page.

Failures shows scheduled backup, task, and cleanup executions that did not finish successfully.

### Filter failures

<ZoomableImage src="shadow-todo" alt="Type Filter setting screenshot" />

Filters the failures list by the kind of scheduled work and when it happened.

Use **Filter** to choose the relevant criteria and review the results. Use the search field to find matching failure details.

**Accepted values:**

- `all`, `backup`, `task`, or `cleanup`.

---

### Failure Table

**Accepted values:**

- `server_not_functional`, `subscription_unpaid`, `database_deleted`, `server_deleted`, `resource_deleted`, `application_not_running`, `service_not_running`, or another internal reason label.
