# Sentinel

[Sentinel](https://github.com/coollabsio/sentinel) is the lightweight agent Coolify runs on a connected server. It reports server and container health to your Coolify instance and can collect the data used by CPU and memory charts.

<CoolCallout icon={ArrowsRight} title="The short version">

Coolify runs Sentinel as the `coolify-sentinel` container on each eligible server. Sentinel sends authenticated status updates to Coolify and stores metric history locally when metrics are enabled.

</CoolCallout>

<CoolCallout type="warning" icon={Warning22} title="Sentinel is not available on every server">

Sentinel is not available on build servers or Docker Swarm servers. Validate a standard Docker server before configuring Sentinel.

</CoolCallout>

## Enable or sync Sentinel

1. Open **Servers** and select the server.
2. Open **Sentinel > Configuration**.
3. If Sentinel is disabled, select **Enable Sentinel**.
4. If Coolify shows **Out of Sync**, select **Sync**. If Sentinel is already live, the same action is labeled **Restart**.
5. Wait for the server header to show **Sentinel In Sync**.

Sentinel needs a URL it can reach from the connected server. If **Coolify URL** is empty, configure the instance [URL](/core/instance-management/instance-settings#url), return to Sentinel, and sync again.

## Sentinel settings

| Setting | Default | Accepted value and effect |
| :--- | :--- | :--- |
| **Coolify URL** | Generated from the Coolify instance settings | A full URL. Sentinel sends its updates to this address. |
| **Sentinel token** | Generated by Coolify | A required authentication token. Use **Regenerate** instead of creating your own token. |
| **Metrics rate (seconds)** | `10` | An integer of `1` or greater. Lower values collect more samples and use more disk space. |
| **Metrics history (days)** | `7` | An integer of `1` or greater. Sentinel removes metric history beyond this period. |
| **Push interval (seconds)** | `60` | An integer of `10` or greater. This controls how often Sentinel sends server and container information to Coolify. |

Select **Save** after changing a setting. Changes to the URL, token, metric rate, metric history, or push interval restart Sentinel so the running container receives the new values.

Treat the Sentinel token as a secret. Coolify encrypts it in the instance database and sends it to the Sentinel container as an environment variable.

## Troubleshooting

<Accordions type="multiple">

<Accordion title="Sentinel stays Out of Sync">

Confirm that the server is validated and shown as reachable in Coolify. Then open **Sentinel > Configuration** and select **Sync**.

If Sentinel remains out of sync, open **Sentinel > Logs** and read the `coolify-sentinel` container output.

After recovery, confirm that the server header changes to **Sentinel In Sync** and that its timestamp continues to update.

</Accordion>

<Accordion title="Coolify URL is empty or unreachable">

Sentinel needs a **Coolify URL** that the connected server can reach.

If the field is empty, configure the instance [URL](/core/instance-management/instance-settings#url), return to **Sentinel > Configuration**, and select **Sync** again.

</Accordion>

<Accordion title="Sentinel logs show an authorization error">

Open **Sentinel > Configuration** and select **Regenerate** beside **Sentinel token**.

Coolify creates a new token and restarts Sentinel. Confirm that the server returns to **Sentinel In Sync**.

</Accordion>

</Accordions>
