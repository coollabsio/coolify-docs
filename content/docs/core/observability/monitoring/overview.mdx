# Monitoring overview

Coolify tracks the state of connected servers and the workloads running on them. The dashboard shows current status, while notification channels can report selected failures and operational events to your team.

<CoolCallout icon={ArrowsRight} title="The short version">

[Sentinel](/core/observability/monitoring/sentinel) provides the preferred server-to-Coolify status path on supported servers. [Metrics](/core/observability/monitoring/metrics) adds historical CPU and memory charts. Metrics can be disabled while Sentinel continues to report server and container health.

</CoolCallout>

## Monitoring boundaries

Built-in monitoring provides platform and container visibility, but it is not a complete external observability system.

<CoolCompare
  id="monitoring-boundaries"
  className="not-prose"
  icon={ShieldSecurity2}
  title="What Coolify covers"
  description="Use external tools when you need endpoint checks, threshold alerting, long-term analysis, or provider-managed retention."
>
<CoolCompareColumn
  title="Built into Coolify"
  items={[
    'Server reachability, validation state, and disk usage checks',
    'Container state and Docker health information',
    'Historical CPU and memory charts when Sentinel metrics are enabled',
    'Selected operational notifications and workload log forwarding',
  ]}
/>
<CoolCompareColumn
  title="Requires an external system"
  items={[
    'CPU or memory threshold alerts from the built-in charts',
    'Public endpoint checks from outside your infrastructure',
    'Application workflow checks beyond the health endpoint you configure',
    'Log retention, queries, dashboards, and log-based alerts',
  ]}
/>
</CoolCompare>

Log drains forward workload container output. They do not forward Coolify deployment logs or replace the retention and alerting controls in your log provider.
