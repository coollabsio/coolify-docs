# Remove a server

Deleting a server always removes it's details from the Coolify database. Depending on the options you choose, Coolify can also delete its managed resources and its linked Hetzner, DigitalOcean, or Vultr machine.

The **localhost** server in a self-hosted Coolify installation cannot be deleted.

<Callout type="error" title="Back up important data first">
Deleting resources or the linked provider machine can permanently destroy application files, databases, volumes, and backups stored on that machine.
</Callout>

## Decide what to delete

Before opening the deletion dialog, choose the required outcome.

| Option | Result |
| :--- | :--- |
| **Only delete server from Coolify** | Removes the server from Coolify. The Linux machine, Docker installation, and files remain. |
| **Delete all resources** | Starts deletion for every resource Coolify manages on this server, then removes the server from database. |
| **Also delete server/droplet from the provider** | Sends a deletion request for the linked Hetzner server, Vultr instance, or DigitalOcean Droplet. |

Provider deletion is not selected by default. If you leave it disabled, the provider continues billing for a machine that still exists.

---

## Prepare for removal

<Steps>
<Step>

### Review managed resources

1. Open **Servers** and select the server.
2. Open **Resources > Managed**.
3. Review every listed application, database, and service.

Back up important data. Redeploy resources you want to keep to another server and update their DNS records.

</Step>
<Step>

### Choose how resources will be handled

For the safest and most controlled migration, move or delete each resource before removing the server.

If resources remain, the confirmation dialog offers **Delete all resources** and shows how many will be deleted. Enable it only if every remaining resource can be destroyed.

</Step>
<Step>

### Check the provider link

If the server is linked to Hetzner, DigitalOcean, or Vultr, decide whether the actual provider machine should also be deleted.

Keep the provider option disabled if you need the machine, its files, or console access after removing it from Coolify.

</Step>
</Steps>

---

## Delete the server

<Steps>
<Step>

### Open the Danger Zone

Open the server's **Danger** page and find **Delete Server** under **Danger Zone**.

</Step>
<Step>

### Review the confirmation

Select **Delete** and review every action shown in the dialog.

When applicable:

- enable **Delete all resources** only if the remaining managed resources can be destroyed
- enable **Also delete server from Hetzner Cloud** only if the linked Hetzner server should be permanently deleted
- enable **Also delete server from Vultr** only if the linked Vultr instance should be permanently deleted
- enable **Also delete droplet from DigitalOcean** only if the linked DigitalOcean Droplet should be permanently deleted

Enter the required confirmation value and complete the deletion.

</Step>
<Step>

### Verify the result

Confirm that the server no longer appears on the **Servers** page.

If you selected provider deletion, open the provider console and confirm that the machine was deleted. If it still exists, delete it through the provider console to prevent unexpected charges.

</Step>
</Steps>

<Callout type="info" title="Removing only the Coolify record does not clean the machine">
Coolify does not uninstall Docker or remove application files merely because you delete the server record. Clean up or repurpose the machine yourself if it remains at the provider.
</Callout>

---

## Add the machine again

There is no restore action for a deleted server record.

If the Linux machine still exists, follow [Add Server](/core/infrastructure/servers/add-server) and validate it again. This creates a new Coolify server record.

Applications, databases, and services from the deleted record do not automatically return, even if their containers or files remain on the machine. Recreate or redeploy each resource that Coolify should manage.
