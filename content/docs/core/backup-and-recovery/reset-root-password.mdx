# Reset Root Password

Reset the root password from the server terminal when you cannot sign in to the root account and cannot use an emailed password-reset link.

<Callout type="warning" title="Self-hosted instances only">
Coolify Cloud users cannot access the container that runs this command. If you cannot access your Coolify Cloud account, [contact the Coolify team](/support).
</Callout>

## Choose the right recovery method

Use the least disruptive method available:

- If you are signed in and know the current password, open **Profile > General**, enter the current and new passwords under **Change Password**, then select **Save**.
- If you can receive transactional email from the instance, select **Forgot Password** on the login page and use the emailed reset link.
- If neither option is available, use the terminal procedure below. It does not require the current root password or a working email configuration.

## Before you reset the password

Make sure you have:

- SSH access to the server that runs the self-hosted Coolify instance
- permission to run Docker commands on that server
- the root account's current login email, or a plan to [change the root email](/core/backup-and-recovery/change-root-email) after the reset
- a strong, unique password ready to enter twice

The terminal command checks only that both password entries match. It does not enforce the password rules used by the Coolify dashboard. Use a long, randomly generated password that you do not use for another account, and store it in a password manager.

<Callout type="warning" title="Root sessions and API tokens will be revoked">
After the password changes, Coolify signs the root account out on every device and revokes every API token owned by that account. Sessions and API tokens for other users are not affected.
</Callout>

## Reset the root password

<Steps>
<Step>

### Connect to the Coolify server

Connect over SSH to the machine that runs the Coolify control plane:

```sh
ssh root@<server-ip>
```

Replace `<server-ip>` with the server's IP address. If you connect as a non-root user, that account must have permission to run Docker commands. Add `sudo` before the Docker commands below when your server requires it.

</Step>
<Step>

### Confirm that the Coolify container is running

```sh
docker inspect --format '{{.State.Status}}' coolify
```

The command should print `running`. If Docker reports that the `coolify` container does not exist or is not running, [update or repair the Coolify installation](/core/instance-management/update) before continuing.

</Step>
<Step>

### Run the password-reset command

```sh
docker exec -it coolify php artisan root:reset-password
```

Coolify displays these interactive prompts:

```console
You are about to reset the root password.
Give me a new password for root user:
Again:
```

Type the new password at the first prompt, then type the same password again. The terminal does not display the password while you type.

When both entries match and the root account exists, Coolify prints:

```console
Updating root password...
Root password updated successfully.
```

The command updates only the root account password. It does not restart Coolify or interrupt deployed applications, databases, or services.

</Step>
</Steps>

## Verify root access

Open the Coolify login page in a private browser window and sign in with:

- the root account's current email
- the new password
- the root account's two-factor authentication code, if 2FA is enabled

Using a private window verifies a fresh login without relying on an existing browser session. Existing root sessions should no longer open the dashboard after the password change.

<Callout type="info" title="Replace revoked API tokens">
If an integration used an API token owned by the root account, create a replacement token after signing in and update that integration. The revoked token cannot be restored.
</Callout>

## If the reset fails

<Accordions type="multiple">

<Accordion title="Passwords do not match">

The two entries were different, so Coolify did not change the password. Run the command again and enter the same value at both prompts.

</Accordion>

<Accordion title="Root user not found">

The instance database does not contain the root account at user ID `0`. Do not create or edit the database record manually. Confirm that you connected to the correct Coolify server, then [restore the instance database](/core/backup-and-recovery/instance-restore) from a known backup or [contact support](/support).

</Accordion>

<Accordion title="Failed to update root password">

Coolify found the command but could not save the new password. Confirm that the `coolify-db` container is running:

```sh
docker inspect --format '{{.State.Status}}' coolify-db
```

If the command does not print `running`, repair the Coolify installation before retrying. If the database is running and the reset still fails, keep the command output and [contact support](/support).

</Accordion>

<Accordion title="The command succeeded but login still fails">

Confirm that you are using the root account's current email and the exact password entered in the terminal. If you no longer know or cannot use the root email, follow [Change Root Email](/core/backup-and-recovery/change-root-email), then try a fresh login again.

If 2FA blocks the login after the password is accepted, follow [Reset 2FA](/core/backup-and-recovery/reset-2fa).

</Accordion>

</Accordions>
