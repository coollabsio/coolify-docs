# Browse container files

Open a running application, standalone database, or service and select **Files**. The file browser reads the container's filesystem and lets you manage files without opening a terminal.

You need permission to access the resource and to use the terminal. Team Members cannot use the file browser. The container must be running and its server reachable.

## Open a container and folder

For a multi-container resource, select the container you want to inspect. Open folders from the listing, use the breadcrumbs to return to a parent, or enter a path. Select **Refresh** to reload the current folder after an external change.

The browser shows container paths. A host directory appears only where it is mounted inside that container. See [Storage mounts](/core/persistent-storage/storage-mounts/overview) to find the mount's container destination.

## Manage files

| Action | Behavior |
| :--- | :--- |
| Create file or folder | Adds an entry in the current folder. |
| Edit | Opens a text file in the editor. Save to write changes into the running container. Binary files and files larger than 5 MB cannot be edited here. |
| Upload | Uploads a file to the current folder. Use the upload control or drag a file into the listing. The application limit is 1 GiB; proxy and upload settings can impose lower limits. |
| Rename | Changes the selected entry's name. |
| Permissions | Select the permissions to enter an octal mode, such as `644` for a file or `755` for a folder. |
| Delete | Permanently removes the selected file or folder after confirmation. |
| Download | Downloads a file, or packages a folder as a `.tar.gz` archive. |

<Callout type="warning" title="Changes affect the running workload">
Edits and deletions take effect in the container immediately. Files outside persistent mounts can disappear when the container is replaced. Changes made here do not update your Git repository, Docker image, or Coolify file-mount definition. Keep durable configuration in its source and back up persistent data before changing it.
</Callout>

For database files, use the database's [backup and restore workflow](/databases/backups) rather than editing live data files.

## Download methods and limits

By default, Coolify streams downloads through the instance. The file browser supports files and folders up to 1 GiB with this method.

An instance administrator can choose a usable S3 storage in **Settings > Advanced > File downloads > Download method**. Then the managed server uploads the file to S3 and the browser downloads it from there. This raises the file-browser limit to 5 GiB. Folder limits are checked against the folder's size before archiving.

With S3 downloads:

- Wait while Coolify prepares the file. The download starts when it is ready.
- Links expire after 15 minutes. Start a new download if the link expires.
- Temporary files are scheduled for deletion after six hours. A bucket lifecycle rule removes objects under `coolify-file-downloads/` after one day as a fallback.
- Each user can prepare up to three downloads concurrently and start up to ten preparations per hour.

For larger files, use a terminal transfer or a [volume backup](/core/persistent-storage/storage-mounts/backups).

## Configure S3 downloads

1. Add and validate a private S3 bucket in the instance team. The storage must be reachable from both the managed servers and users' browsers.
2. Open **Settings > Advanced > File downloads**.
3. Set **Download method** to that S3 storage.

The provider must support bucket lifecycle rules, and the credentials must allow Coolify to configure them. Coolify rejects buckets that permit anonymous listing and endpoints that use an internal Docker hostname. This temporary download storage is separate from the S3 destinations selected on backup schedules.

The setting also applies to downloads of local backup archives. Backups larger than 5 GiB continue to stream through Coolify.

## Troubleshooting

| Problem | Next step |
| :--- | :--- |
| The container is stopped | Start it from the resource page, then reopen Files. |
| Files cannot be loaded | Check the server connection and select **Retry**. |
| A file cannot be edited | Download it if it is binary or larger than the editor limit. |
| Download is too large | Use a terminal transfer or a volume backup. |
| S3 setup fails | Check bucket privacy, endpoint reachability, lifecycle support, and credential permissions. |
| Too many downloads are in progress | Wait for pending preparations to finish and respect the hourly limit. |
