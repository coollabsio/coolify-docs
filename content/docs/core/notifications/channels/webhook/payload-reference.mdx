# Webhook payload reference

Coolify sends webhook notifications as JSON `POST` requests to the endpoint configured under **Notifications > Webhook**. Follow [Webhook setup](/core/notifications/channels/webhook/setup) before using this reference.

Requests use the `Content-Type: application/json` header. Every payload includes these fields:

| Field | Type | Description |
|-------|------|-------------|
| `success` | boolean | `true` for success events; `false` for failures and alerts. |
| `event` | string | Machine-readable event identifier. |
| `message` | string | Human-readable event summary. |

Select an event identifier in each section to inspect its request body and conditional fields.

## Application deployments and status

<Tabs id="webhook-application-events" items={['deployment_success', 'deployment_failed', 'status_changed', 'restart_limit_reached']}>
<Tab value="deployment_success" icon={CheckCircle}>

Sent when an application deployment completes successfully.

```json
{
  "success": true,
  "event": "deployment_success",
  "message": "New version successfully deployed",
  "application_name": "my-app",
  "application_uuid": "...",
  "deployment_uuid": "...",
  "deployment_url": "...",
  "project": "...",
  "environment": "...",
  "fqdn": "..."
}
```


<Callout type="info" title="Pull request previews">

Pull request preview deployments add these fields:

```json
{
  "pull_request_id": 123,
  "preview_fqdn": "..."
}
```

</Callout>

`fqdn` is included when the application has a domain. It may be absent from either regular or preview deployment payloads.

</Tab>
<Tab value="deployment_failed" icon={Warning22}>

Sent when an application deployment fails.

```json
{
  "success": false,
  "event": "deployment_failed",
  "message": "Deployment failed",
  "application_name": "my-app",
  "application_uuid": "...",
  "deployment_uuid": "...",
  "deployment_url": "...",
  "project": "...",
  "environment": "...",
  "fqdn": "..."
}
```

Same structure as `deployment_success`, with `"success": false`. PR preview fields apply in the same way.

</Tab>
<Tab value="status_changed" icon={Refresh23}>

Sent when an application, preview, service, or database stops unexpectedly and is still stopped after 2 minutes. A stop from Coolify does not send this event. See [Resource status changes](/core/notifications/events#resource-status-changes).

```json
{
  "success": false,
  "event": "status_changed",
  "message": "Resource stopped",
  "status": "exited",
  "application_name": "my-app",
  "application_uuid": "...",
  "resource_name": "my-app",
  "resource_uuid": "...",
  "url": "...",
  "project": "...",
  "environment": "...",
  "fqdn": "..."
}
```

`resource_name` and `resource_uuid` identify the stopped resource of any type. `application_name` and `application_uuid` contain the same values, for existing receivers.

</Tab>
<Tab value="restart_limit_reached" icon={NotifRemove}>

Sent when Coolify stops an application after it reaches its automatic restart limit. This event uses the **Resources > Restart limit reached** notification selection.

```json
{
  "success": false,
  "event": "restart_limit_reached",
  "message": "Restart limit reached",
  "application_name": "my-app",
  "application_uuid": "...",
  "restart_count": 10,
  "max_restart_count": 10,
  "url": "...",
  "project": "...",
  "environment": "...",
  "fqdn": "..."
}
```

</Tab>
</Tabs>

## Scheduled tasks

<Tabs id="webhook-task-events" items={['task_success', 'task_failed', 'task_disabled']}>
<Tab value="task_success" icon={CheckCircle}>

Sent when a scheduled task completes successfully.

```json
{
  "success": true,
  "event": "task_success",
  "message": "Scheduled task succeeded",
  "task_name": "...",
  "task_uuid": "...",
  "output": "...",
  "application_uuid": "...",
  "url": "..."
}
```

</Tab>
<Tab value="task_failed" icon={Warning22}>

Sent on the first failure of a scheduled task, then at most once a day while it keeps failing. See [Repeated failures](/core/notifications/events#repeated-failures).

```json
{
  "success": false,
  "event": "task_failed",
  "message": "Scheduled task failed",
  "task_name": "...",
  "task_uuid": "...",
  "output": "...",
  "consecutive_failures": 3,
  "application_uuid": "...",
  "url": "..."
}
```


<Callout type="info">

`application_uuid` is included for application-level tasks. For service-level tasks, `service_uuid` is included instead. `url` is only present when available.

</Callout>

</Tab>
<Tab value="task_disabled" icon={NotifRemove}>

Sent once when Coolify disables a scheduled task after 10 failed runs in a row and the first of these failures is more than 24 hours old. This event uses the **Scheduled task failure** selection.

```json
{
  "success": false,
  "event": "task_disabled",
  "message": "Scheduled task disabled",
  "task_name": "...",
  "task_uuid": "...",
  "output": "...",
  "consecutive_failures": 10,
  "application_uuid": "...",
  "url": "..."
}
```

The conditional fields are the same as for `task_failed`.

</Tab>
</Tabs>

## Recovery events

Sent once on the first successful run after Coolify sent a failure notification for a scheduled job. A recovery event uses the selection of the failure event, for example **Backup failure**.

| Event | Job | Failure selection | Extra fields |
|-------|-----|-------------------|--------------|
| `task_recovered` | Scheduled task | **Scheduled task failure** | `task_name`, `task_uuid` |
| `backup_recovered` | Database backup | **Backup failure** | `database_name`, `database_uuid`, `backup_uuid` |
| `volume_backup_recovered` | Storage backup | **Backup failure** | `backup_uuid` |
| `docker_cleanup_recovered` | Docker cleanup | **Docker cleanup failure** | `server_name`, `server_uuid` |

```json
{
  "success": true,
  "event": "backup_recovered",
  "message": "Database backup for my-database works again.",
  "database_name": "my-database",
  "database_uuid": "...",
  "backup_uuid": "...",
  "url": "..."
}
```

`url` is only present when available.

## Server events

<Tabs id="webhook-server-events" items={['server_reachable', 'server_unreachable', 'server_ssh_host_key_changed', 'high_disk_usage', 'server_patch_check', 'server_patch_check_error', 'traefik_version_outdated']}>
<Tab value="server_reachable" icon={Server}>

Sent when a previously unreachable server becomes reachable again.

```json
{
  "success": true,
  "event": "server_reachable",
  "message": "Server revived",
  "server_name": "...",
  "server_uuid": "...",
  "url": "..."
}
```

</Tab>
<Tab value="server_unreachable" icon={ServerCloud}>

Sent when Coolify cannot reach a server.

```json
{
  "success": false,
  "event": "server_unreachable",
  "message": "Server unreachable",
  "server_name": "...",
  "server_uuid": "...",
  "url": "..."
}
```

</Tab>
<Tab value="server_ssh_host_key_changed" icon={Warning22}>

Sent when the SSH host key of a server does not match the key that Coolify trusts. This event uses the **Server unreachable** selection. `url` opens the SSH host key section of the server's **Security** page.

```json
{
  "success": false,
  "event": "server_ssh_host_key_changed",
  "message": "SSH host key changed",
  "server_name": "...",
  "server_uuid": "...",
  "url": "..."
}
```

</Tab>
<Tab value="high_disk_usage" icon={HardDrive}>

Sent when disk usage on a server exceeds the configured threshold.

```json
{
  "success": false,
  "event": "high_disk_usage",
  "message": "High disk usage detected",
  "server_name": "...",
  "server_uuid": "...",
  "disk_usage": 85,
  "threshold": 80,
  "url": "..."
}
```

`disk_usage` and `threshold` are integer percentages.

</Tab>
<Tab value="server_patch_check" icon={ServerUpdate}>

Sent when available OS patches are detected on a server.

```json
{
  "success": false,
  "event": "server_patch_check",
  "message": "Server patches available",
  "server_name": "...",
  "server_uuid": "...",
  "total_updates": 12,
  "os_id": "ubuntu",
  "package_manager": "apt",
  "updates": [...],
  "critical_packages_count": 2,
  "url": "..."
}
```

</Tab>
<Tab value="server_patch_check_error" icon={Warning22}>

Sent when Coolify cannot complete the server patch check.

```json
{
  "success": false,
  "event": "server_patch_check_error",
  "message": "Failed to check patches",
  "server_name": "...",
  "server_uuid": "...",
  "os_id": "ubuntu",
  "package_manager": "apt",
  "error": "...",
  "url": "..."
}
```

</Tab>
<Tab value="traefik_version_outdated" icon={Route}>

Sent when one or more servers are running an outdated version of the Traefik proxy.

```json
{
  "success": false,
  "event": "traefik_version_outdated",
  "message": "Traefik proxy outdated",
  "affected_servers_count": 1,
  "servers": [
    {
      "name": "...",
      "uuid": "...",
      "current_version": "v3.1.0",
      "latest_version": "v3.1.4",
      "update_type": "patch_update",
      "upgrade_target": "v3.2",
      "newer_branch_target": "...",
      "newer_branch_latest": "..."
    }
  ]
}
```

| Field | Description |
|-------|-------------|
| `update_type` | `patch_update` or `minor_upgrade` |
| `upgrade_target` | Target minor version — only present for `minor_upgrade` |
| `newer_branch_target` / `newer_branch_latest` | Present when a newer major/minor branch is available |

</Tab>
</Tabs>

## Image vulnerabilities

These events use the **Resources > Image vulnerabilities** selection. They do not contain vulnerability IDs.

<Tabs id="webhook-image-events" items={['image_exploited_problem', 'image_vulnerabilities_digest']}>
<Tab value="image_exploited_problem" icon={Warning22}>

Sent right after a scan finds new problems in a resource that attackers are using or are likely to use.

```json
{
  "success": false,
  "event": "image_exploited_problem",
  "message": "Update now",
  "resource_name": "api",
  "resource_uuid": "...",
  "url": "...",
  "status": "update_now",
  "text": "api: problems that attackers are using. Update to 1.28.",
  "action": "Update to 1.28."
}
```

| Field | Description |
|-------|-------------|
| `status` | `update_now` when an update fixes the problems, `check_needed` when Coolify could not check for a fixed version yet, or `no_fix` when no fixed version exists yet. |
| `message` | The status as text: `Update now`, `Check needed`, or `No fix yet`. |
| `action` | The update that fixes the most problems, or `null`. |

</Tab>
<Tab value="image_vulnerabilities_digest" icon={ServerUpdate}>

The daily security digest of the team. Coolify sends it only when something changed.

```json
{
  "success": false,
  "event": "image_vulnerabilities_digest",
  "message": "Daily security digest",
  "url": "...",
  "resources": [
    {
      "name": "...",
      "uuid": "...",
      "url": "...",
      "status": "update_available",
      "action": "..."
    }
  ],
  "ignores_ending": false,
  "servers_failing": [
    {
      "name": "...",
      "url": "..."
    }
  ]
}
```

| Field | Description |
|-------|-------------|
| `resources` | Resources with a new status or a new fixing version. `status` is the security status of the resource, for example `update_now`, `update_available`, or `check_needed`. |
| `ignores_ending` | `true` when ignored vulnerabilities have an ignore that ends within 7 days. |
| `servers_failing` | Servers whose scans failed 2 days in a row. |

</Tab>
</Tabs>

## Always-sent events

These events have no event setting. Coolify sends them to every enabled webhook. See [Notifications that are always sent](/core/notifications/events#notifications-that-are-always-sent).

<Tabs id="webhook-always-events" items={['api_token_failing', 'general']}>
<Tab value="api_token_failing" icon={Warning22}>

Sent when an API token of the team reaches the limit of failed requests. Coolify sends it at most once a day for each token.

```json
{
  "success": false,
  "event": "api_token_failing",
  "message": "API token 'ci' sent 30 failed requests in one minute. Coolify now answers its requests with 429 (Too Many Requests) until the failures stop.",
  "token_name": "ci",
  "failed_requests": 30,
  "last_request": "GET /api/v1/applications → 403",
  "url": "..."
}
```

`failed_requests` is the configured limit. `url` opens the API tokens page.

</Tab>
<Tab value="general" icon={ServerCloud}>

A general message, for example about an automatic update of Coolify to the root team, or that Coolify [turned off a notification channel](/core/notifications/overview#disabled-channels).

```json
{
  "success": true,
  "event": "general",
  "message": "Automatic update finished: Coolify is now on 4.7.1.",
  "url": "..."
}
```

`success` is `false` for failure messages, for example `Automatic update failed: ...`. `url` is the URL of the Coolify instance.

</Tab>
</Tabs>
