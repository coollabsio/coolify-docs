# Automation

| Tool | Purpose |
| :--- | :--- |
| `list_scheduled_tasks` | List scheduled tasks for an application or service. |
| `list_scheduled_task_executions` | List recent executions for a scheduled task. |
| `list_unhealthy_resources` | Find resources that appear unhealthy or down; use `sample_only=true` for a cheap first check. |
| `get_infrastructure_overview` | Return SQL-based health-hint counts and open deployment counts. |

Task command bodies and execution messages require `read:sensitive` and are best-effort redacted.

## Manage scheduled tasks

| Tool | Actions |
| :--- | :--- |
| `manage_scheduled_task` | `create`, `update` (`write`); `delete` (`delete`, confirm); `execute` (`deploy`, confirm). An enabled task also needs `deploy`. |

Actions marked **confirm** need `confirm=true`. Ask the user before your client sends it.

`create` and `update` accept `use_shell`, the **Run in a shell** setting. It defaults to `true`: the command runs with `sh -c` in the container. Set it to `false` for containers without a shell. The command then runs directly, without shell features such as variables, pipes, or redirects.
