# Set up MCP

Set up Coolify MCP by enabling the instance endpoint, confirming team access, creating a token, and adding the endpoint to your AI client.

## Before you begin

- Use Coolify Cloud or a self-hosted Coolify instance with a public HTTPS URL.
- Choose the team whose resources the client must access.
- Create an API token with the smallest required permissions. See [API tokens](/core/security/credentials/api-tokens).

<Callout type="warning" title="Self-hosted: MCP is off by default">
On a self-hosted instance, you must turn on MCP for the instance before a client can connect. Open **Settings > Advanced**, find the **API and MCP** section, and set **MCP server** to **Enabled**. Until you do this, `/mcp` returns `404`.

On Coolify Cloud, MCP is already enabled. You do not have to change this setting.
</Callout>

<Callout type="warning" title="Protect the token">
An MCP client can use every operation allowed by its token. Store the token in the client's secret configuration, never commit it, and revoke it if exposed.
</Callout>

## Example values

This guide uses Coolify Cloud in its examples. If you use a self-hosted Coolify instance, replace `app.coolify.io` with your instance's domain in every URL, and use your own token:

<Callout type="info" title="Example data">

- **Coolify URL:** `https://app.coolify.io`
- **MCP endpoint:** `https://app.coolify.io/mcp`
- **API token:** `67|abcthisisa123dummytoken`

</Callout>

<Step>

### Enable MCP

<Callout type="info" title="Coolify Cloud">
Coolify Cloud already has instance MCP enabled. Skip the Dashboard and API tabs, then continue to [Create an MCP token](#create-an-mcp-token). Team access remains enabled by default, but check team settings if a client receives `403`.
</Callout>

<Tabs items={['Dashboard', 'API']}>
<Tab value="Dashboard">

<ZoomImage src="/docs/images/mcp/enable-mcp.webp" alt="Coolify Advanced settings with MCP server enabled" />

This step is required on self-hosted instances. Only an instance admin (a member of the root team) can change it.

1. Open **Settings** in the sidebar.
2. Open **Advanced**.
3. In the **API and MCP** section, set **MCP server** to **Enabled**. Coolify saves the change immediately.

The **API access** setting does not control MCP. MCP works when the REST API is disabled.

MCP must also be enabled for the team of the token. It is enabled by default. To check it, open **Team > General**, make sure **MCP server** is **Enabled for this team**, then select **Save changes**. Team admins and owners can change this setting.

If you use **Allowed IPs** in **Settings > Advanced**, the list also applies to `/mcp`. Add the IP address of the machine that runs the MCP client.

</Tab>
<Tab value="API">

On a self-hosted instance, use a `write` or `root` API token of the root team to enable or disable the instance endpoint. Replace the example URL with your instance's domain:

```sh
export COOLIFY_URL="https://coolify.example.com"
export COOLIFY_ROOT_TOKEN="67|abcthisisa123dummytoken"

curl --fail-with-body --request POST \
  --header "Authorization: Bearer $COOLIFY_ROOT_TOKEN" \
  "$COOLIFY_URL/api/v1/mcp/enable"
```

The endpoint returns `MCP server enabled.`. Disable it with `POST /api/v1/mcp/disable`.

These endpoints require a token with `write` or `root` that belongs to the root team (team ID `0`). A token of any other team receives `403`.

</Tab>
</Tabs>

</Step>
<Step>

### Create an MCP token

Create a token from **Keys & Tokens > API Tokens** while the required team is active.

Coolify displays the complete token only once. Copy it into the client's secret configuration before leaving the API Tokens page.

- Use `read` for inventory and inspection.
- Add `read:sensitive` only for supported sensitive data or log summaries.
- Add `deploy` for deploy, start, stop, restart, cancel, and rollback operations.
- Add `write` to create, update, or delete resources with the `create_*` and `manage_*` tools.
- Do not use `root` for normal MCP clients.

Only team admins and owners can use tokens with `read:sensitive`, `write`, `deploy`, or `root`. A team member can use only `read` tokens. MCP shows only the tools that the token's permissions allow.

MCP endpoint URL:

```txt
https://app.coolify.io/mcp
```

</Step>
<Step>

### Connect a client

Configure the client with:

- **URL:** `https://app.coolify.io/mcp`
- **Transport:** Streamable HTTP
- **Authorization:** `Bearer 67|abcthisisa123dummytoken`

Follow a client guide:

- [Claude Code](/mcp/clients/claude-code)
- [Cursor](/mcp/clients/cursor)
- [Other MCP clients](/mcp/clients/other-clients)

</Step>
<Step>

### Verify access

Ask the client to call `get_current_team` or `get_infrastructure_overview`. The response should contain the team and resources associated with the token.

</Step>
</Steps>
