# Troubleshoot MCP

<Accordions type="multiple">
<Accordion title="The MCP endpoint returns 404">

This is the most common problem on self-hosted instances. MCP is disabled by default.

Open **Settings > Advanced**. In the **API and MCP** section, set **MCP server** to **Enabled**. Coolify saves the change immediately. The endpoint returns `404` while this setting is disabled. Only an instance admin can see this page.

The **API access** setting does not control MCP. On Coolify Cloud, MCP is always enabled.

</Accordion>
<Accordion title="The MCP endpoint returns 403">

Read the message in the response:

- `MCP server is disabled for this team.`: open **Team > General** for the token's team. Set **MCP server** to **Enabled for this team**, then select **Save changes**.
- `You are not allowed to access the API.`: the client IP is not in **Allowed IPs** in **Settings > Advanced**. Add the IP address of the machine that runs the client. This check applies only to self-hosted instances.

</Accordion>
<Accordion title="The client returns 401 or authentication fails">

Confirm the complete token appears after `Bearer`, has not expired, been paused, or been revoked, and that its owner is still a member of the token's team. Confirm the client sends the header on every MCP request. Coolify returns `401` with `Invalid token.` in these cases.

</Accordion>
<Accordion title="The client reports error -32003: This API token has more access than you have in this team">

The token has more access than its owner has in the token's team. For example, the owner's access changed after the token was created. Revoke the token and create a new one with the access you have, or ask a team admin or owner to give you more access.

</Accordion>
<Accordion title="The client cannot connect">

Confirm the URL ends with `/mcp`, the instance is reachable from the client machine, HTTPS is valid, and transport is **Streamable HTTP**. Do not configure SSE or stdio for Coolify's remote endpoint.

</Accordion>
<Accordion title="A tool reports missing permissions">

Use `read` for inspection, `read:sensitive` for supported sensitive output, `deploy` for deployment or lifecycle operations, `write` for `create_*` and `manage_*` tools, and `delete` for delete actions. `write` does not include `delete`. MCP hides tools that the token cannot use. A token limited to selected projects, environments, or resources also does not see team-level tools, such as the server tools. Call `coolify_help` to see the tools that the token can use.

</Accordion>
<Accordion title="A resource is missing">

MCP returns only resources owned by the token's team. Create or use a token for the team that owns the resource. Start with `get_current_team` or `get_infrastructure_overview` to inspect the token's scope.

</Accordion>
<Accordion title="Logs are unavailable">

`get_logs` requires `read:sensitive`, a running container, and a reachable server. For a failed deployment, call `get_deployment` first and request an optional log summary only when needed.

</Accordion>
<Accordion title="Environment values are missing">

Use `list_env_keys` for names only. To retrieve values, use `get_env_values` with both `read` and `read:sensitive`; the token owner must be an Admin or Owner of the team. Locked values are never returned.

</Accordion>
<Accordion title="An action requires confirmation">

Review the target and the action's effect, then allow the client to retry with `confirm=true` if you intend that change. This applies to destructive actions, some operations that interrupt workloads, and paid cloud-server provisioning.

</Accordion>
</Accordions>
