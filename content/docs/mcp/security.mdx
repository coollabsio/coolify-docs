# MCP security

MCP gives an AI client access to Coolify data and, when permitted, lifecycle operations. Treat the token as a password.

## Use least privilege

| Need | Permission |
| :--- | :--- |
| Inspect resources | `read` |
| Read supported sensitive data or log summaries | `read:sensitive` |
| Deploy, start, stop, restart, cancel, or roll back | `deploy` |
| Create or update resources (create and update actions of `create_*` and `manage_*` tools) | `write` |
| Delete resources, environment variables, storages, backups, scheduled tasks, or tags, or detach a tag | `delete` |
| Change the instance MCP setting with the API | `write` or `root` token of an instance admin, in the root team |

`write` does not include `delete`. A `root` token has every permission. Each action of a `manage_*` tool has its own permission, and some list and get actions need only `read` or `read:sensitive`. Some actions need two permissions, for example a registry login needs `write` and `deploy`. The [capability pages](/mcp/capabilities/overview) show the permission of each action.

MCP hides the deployment tools, `get_logs`, and the `create_*` and `manage_*` actions that the token's permissions do not allow. Most read tools are listed also for a token without `read`. They then return `Missing required permissions: read`.

A token can never do more than its owner can do in the token's team. When the owner loses that access, the token stops working. Destructive actions need `confirm=true`. Configure your client to ask you before it calls them.

Do not use a `root` token for normal MCP access.

## Team scope

A token belongs to one team. MCP cannot use that token to read another team's resources. Team admins and owners can disable MCP for their team without disabling the instance endpoint.

A token can also be limited to selected projects, environments, or resources. MCP then returns only those resources and hides the team-level tools, for example the server, private key, Git source, S3 storage, and notification tools.

## Protect client configuration

- Store tokens in the client's secret storage.
- Do not commit MCP configuration containing a token.
- Do not paste tokens into prompts or chat transcripts.
- Restrict access to the machine and user account running the client.
- Revoke the token immediately if exposed.

MCP responses never return private keys, S3 secrets, tokens, passwords, or webhook URLs. Environment values are returned only by `get_env_values` (`read:sensitive`, team admin or owner), and never for values marked as shown once. Log and deployment summaries can still contain operational data; redaction is best effort.

## Approve changes deliberately

Management tools can delete resources and backup files, overwrite configuration, stop workloads, or purchase cloud servers. Review the target and effects before allowing a client to submit `confirm=true` for an action that requires confirmation. A confirmation flag does not grant missing token permissions.

Granting `write` also allows changes to environment variables, scheduled commands, proxy settings, and notification configuration. Granting `delete` allows the client to delete resources and their data. Use a read-only token when the client only needs to inspect resources.

On self-hosted instances, MCP uses its own enable switch and the **Allowed IPs** allowlist. Disabling REST **API access** does not disable MCP; disable **MCP server** or revoke the token to remove MCP access.
